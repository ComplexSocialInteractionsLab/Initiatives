What does this mean?

Smaller embeddings can reduce vector-index storage and memory requirements. Retrieval quality may change with dimensionality, so evaluate the chosen dimension on your own legal corpus and task.

Dimensions Relative storage Reduction Storage multiplier
768 100% 0% 1×
512 66.7% 33.3% 1.5× smaller
256 33.3% 66.7% 3× smaller
128 16.7% 83.3% 6× smaller

Calculations assume the same numeric precision and storage representation per dimension. They describe vector payloads, not total model size, runtime memory, or complete database size. Use these dimensions only if the actual model and inference pipeline support them.

04 / UNDER THE HOOD

Three pieces. Different jobs.

Quantization, embedding dimensionality, and vector retrieval address different parts of a local search system.

GGUF + Q4_K_M

GGUF is a model-file format used by supported local inference runtimes. Q4_K_M is a 4-bit-oriented quantization scheme that reduces weight storage relative to higher-precision representations.

Model footprint

MRL dimensions

Supported truncated embeddings can reduce the space required to store document vectors. This affects the retrieval index rather than the quantized model's weight file.

Vector footprint

Vector retrieval

A vector index compares query embeddings with document embeddings and returns ranked candidates. The index, corpus, and retrieval logic are separate components of the application.

The GGUF embedding model does not itself transcribe audio, understand raw video, or determine whether an action is lawful. Those capabilities require separate components. Any stage can run locally only when its software and hardware support it.

Python Usage Example 
import torch
from sentence_transformers import SentenceTransformer, util

# 1. Load the fine-tuned model
model = SentenceTransformer('CSI-lab/US-state-law-EmbeddingGemma-2', 
 model_kwargs={
        "torch_dtype": torch.bfloat16,
        "config_kwargs": {
            "load_vision_encoder": False,
            "load_audio_encoder": False
        }
    })

# 2. Define the laws (Your Vector Database)
laws = [
    "RCW 9A.56.030: Theft in the first degree. A person is guilty of theft in the first degree if he or she commits theft of property or services which exceed(s) five thousand dollars in value.",
    "RCW 46.61.502: Driving under the influence. A person is guilty of driving while under the influence of intoxicating liquor...",
    "RCW 9A.36.011: Assault in the first degree. A person is guilty of assault in the first degree if he or she..."
]

# 3. Define the user's search query
user_query = "What dollar amount makes a theft a first degree felony?"

# 4. Encode the documents and the query
query_embedding = model.encode(user_query, convert_to_tensor=True, prompt_name="SearchQuery")
law_embeddings = model.encode(laws, convert_to_tensor=True, prompt_name="Document")

# 5. Calculate Cosine Similarity
cosine_scores = util.cos_sim(query_embedding, law_embeddings)

# 7. Print the top result
best_idx = cosine_scores.argmax().item()
print(f"Top Match: {laws[best_idx]}")
print(f"Similarity Score: {cosine_scores[0][best_idx]:.4f}")
